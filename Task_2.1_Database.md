# Задание 2.1. Проверка отображения заказа в базе данных

**Цель:** Задание 1
Представь: тебе нужно проверить, отображается ли созданный заказ в базе данных.
Для этого: выведи список логинов курьеров с количеством их заказов в статусе «В доставке» (поле `inDelivery = true`).

**Инструменты:**
* Postman (для работы с API)
* Терминал (SSH)
* PostgreSQL (`psql`)

---

### Ход выполнения

**Шаг 1. Подключение к базе данных**
Выполнил подключение к базе данных через терминал с помощью команды:
```bash
psql -U morty -d scooter_rent
```
Пароль: `smith`.

**Шаг 2. Изучение структуры БД и первичная проверка**
Чтобы понять, с какими таблицами и полями предстоит работать, я вывел список всех таблиц с помощью команды `\dt`, а затем детально изучил структуру нужных таблиц `Orders` и `Couriers` с помощью команды `\d "Имя_таблицы"`.
Изначально база данных оказалась пустой. Выполнение целевого SQL-запроса вернуло `0 rows`. Следовательно, для чистоты проверки нужно было создать тестовые данные.

3. С помощью метода `PUT /api/v1/orders/accept/2?courierId=2` привязал по одному заказу к двум разным курьерам. Третий заказ оставил без курьера.

**Шаг 4. Выполнение целевого SQL-запроса**
После наполнения базы я выполнил SQL-запрос:
```sql
SELECT c.login, COUNT(o.id) AS orders_count
FROM "Couriers" c
JOIN "Orders" o ON c.id = o."courierId"
WHERE o."inDelivery" = true
GROUP BY c.login;
```

### Обнаруженный баг

**Фактический результат выполнения запроса:**
В базе данных у двух курьеров (логины `123` и `1234`) отображается по **2** принятых заказа (`orders_count = 2`), хотя через API каждому из них был назначен только **1** заказ.

![Результат с багом](images/db_bug_result.png)

**Вывод:**
Обнаружен баг уровня бэкенда, связанный с дублированием заказов при их принятии. Интересно, что ранее абсолютно такой же баг (YSM-01 и YSM-02) был найден в мобильном приложении, где во вкладке "Мои" карточки принятых заказов дублировались. API-запрос на принятие заказа отрабатывает успешно, но в базу данных запись вставляется дважды (или происходит задвоение на уровне связей). Баг требует передачи разработчикам.
